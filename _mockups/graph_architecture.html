The /send tick as a pydantic-graph

This is what the orchestration would look like if we lifted the eight steps of process_send + _tick into typed graph nodes, and what stays exactly where it is. The agents (chat, classifier, extractor, fact-checker, director) do not become nodes — they remain Pydantic AI agents that a node calls. The graph models the state machine; the agents model the LLM interactions.

01The graph

Each box is one BaseNode subclass. Color encodes the work it does; arrow direction is the static edge declared on the node's return type. The FactCheck retry edge inside FireBeat is drawn as a loopback to make the retry visible — but it is not a graph edge. It lives inside the chat agent's @output_validator, raised as ModelRetry, exactly as it does today.

03The line: graph vs. agent

The clearest single insight in this refactor is the boundary between “state machine” and “LLM interaction.” Today they're intermixed inside _tick and _fire_beat. The graph pulls them apart cleanly:

Stays exactly as it is

  • chat_agent with its @instructions decorators (dossier, plot directive, commitments, player canon, epilogue framing, outbound mode)
  • @output_validator + fact_checker_agent + ModelRetry retry loop
  • history_processors compactor with summary_agent
  • classifier_agent, extractor_agent, director_agent — all kept as Agent instances, called from inside nodes
  • spine.py — find_due_beats, apply_literal_effects, apply_classify_effect, apply_canon_extraction, predicate evaluation
  • Event-sourcing: session.apply(event) is still the only state-write API. Nodes call into it.
  • The encoder (asp_encoder.py) and the drift suite — engine semantics don't change, so neither do they

Becomes graph nodes

  • process_send — disappears. Its body becomes the edge list.
  • _tick — disappears. Its three intertwined concerns split into RetireSatisfiedScenes, DeferInFlightScenes, SelectBeat.
  • _fire_beat — becomes the FireBeat node body. The chat/epilogue branch stays inside the node.
  • _select_beat — becomes the SelectBeat node body. The four-way return becomes the node's typed return signature.
  • The manual TickDecision assembly at the bottom of _tick — gone. Each node appends to GraphRunContext.state; the End node ships the accumulated decision.

04What it actually buys

Wins

  • Three concerns split cleanly. Scene-retire, in-flight-defer, and beat-select are three nodes you can test in isolation. Today they're a 100-line block in _tick that has to be tested through the whole tick.
  • TickDecision becomes graph state, not boilerplate. The manual quality_deltas.extend(…) / canon_writes / canon_drops threading evaporates. Each node updates ctx.state; the End node returns it.
  • Live SSE updates become free. graph.iter() yields after each node — the debug overlay can show "classifier done", "selecting beat…", "rendering" in real time. Today the overlay sees nothing until the whole tick finishes.
  • Per-node Logfire spans automatic. Today every important step opens a span by hand and sets attributes. Pydantic-graph instruments per-node for free.
  • Boot tick unifies. Today _boot_tick and _tick are separate code paths. Boot enters at FindDueBeats and reuses every downstream node — currently impossible without restructuring.

Costs

  • ~700 lines of working orchestration get rewritten. The drift suite stays green (engine semantics unchanged), but every test that monkey-patches _select_beat needs to override SelectBeat instead — mechanical churn across the suite.
  • One more dependency. pydantic-graph is its own package with its own version cadence. The decision-builder helper is pydantic_graph.beta.* — you'd commit to either the verbose stable API or beta surface.
  • Event-sourcing doesn't go away. session.apply(event) is still the only state-write API. Graph state and event-sourced state coexist — you add a layer, you don't replace one.
  • Fact-check loop gets worse in graph form. Keep ModelRetry inside the chat agent. A two-node Render/Validate pair would have to reimplement message-history splicing for retries.

graph formmain.py · ~30 lines + 8 node classes
from pydantic_graph import BaseNode, End, Graph, GraphRunContext

# --- graph state: replaces TickDecision-assembly boilerplate ---
@dataclass
class TickState:
    session: Session
    rec: RecordedSend
    eligible: list[Beat] = field(default_factory=list)
    eligibility_report: list[BeatEligibility] = field(default_factory=list)
    quality_deltas: list[QualityDelta] = field(default_factory=list)
    canon_writes: list[CanonCandidate] = field(default_factory=list)
    canon_drops: list[CanonDropRecord] = field(default_factory=list)
    new_emails: list[Email] = field(default_factory=list)
    plot_fired_threads: set[str] = field(default_factory=set)


# --- one node per concern. Edges are the typed return signatures. ---
@dataclass
class RecordSend(BaseNode[TickState]):
    async def run(self, ctx) -> ClassifyAndExtract:
        ctx.state.rec = record_send(ctx.state.session, self.req)
        return ClassifyAndExtract()

@dataclass
class ClassifyAndExtract(BaseNode[TickState]):
    async def run(self, ctx) -> FindDueBeats:
        cls_res, ext_out = await asyncio.gather(
            classify_in_scope(ctx.state),
            extract_canon(ctx.state),
        )
        apply_classify(ctx.state, cls_res)
        promote_canon(ctx.state, ext_out)
        return FindDueBeats()

# …RetireSatisfiedScenes, DeferInFlightScenes — each ~12 lines…

@dataclass
class SelectBeat(BaseNode[TickState]):
    async def run(self, ctx) -> FireBeat | ChatTurnFallback:
        chosen, method, rat = await select_beat(ctx.state)
        if chosen is None:
            return ChatTurnFallback()
        return FireBeat(chosen=chosen)

@dataclass
class FireBeat(BaseNode[TickState]):
    chosen: Beat
    async def run(self, ctx) -> ChatTurnFallback:
        # chat_agent's @output_validator + ModelRetry untouched
        email, deltas, *_ = await fire_beat(ctx.state, self.chosen)
        ctx.state.new_emails.append(email)
        ctx.state.quality_deltas += deltas
        return ChatTurnFallback()

@dataclass
class ChatTurnFallback(BaseNode[TickState, None, TickDecision]):
    async def run(self, ctx) -> End[TickDecision]:
        if needs_fallback(ctx.state):
            ctx.state.new_emails.append(await chat_turn(ctx.state))
        return End(build_decision(ctx.state))

tick_graph = Graph(nodes=[
    RecordSend, ClassifyAndExtract, FindDueBeats,
    RetireSatisfiedScenes, DeferInFlightScenes,
    SelectBeat, FireBeat, ChatTurnFallback,
])

async def process_send(session, req):
    state = TickState(session=session, rec=...)
    result = await tick_graph.run(RecordSend(req=req), state=state)
    return result.output  # TickDecision

06Verdict

Is this more elegant?

Yes, but modestly. The biggest single win is not the diagram — it's that TickDecision stops being manually assembled. Today every step plumbs quality_deltas / canon_writes / canon_drops through function return values; in the graph form they're just fields on GraphRunContext.state that nodes append to. That mechanical bookkeeping is ~40 lines of _tick that disappear.

The next-biggest win is that streaming partial state to the SSE client becomes feasible — graph.iter() yields after each node, so the debug overlay can show progress live. Today the overlay is silent until the whole tick finishes.

The trap to avoid: don't refactor the chat agent or the fact-checker into nodes. ModelRetry is the right local idiom. The graph's job is the state machine; the agent's job is the LLM interaction; keep them in their lanes and the architecture is genuinely cleaner.

If you do this, the entry point is process_send + _tick — about ~700 lines that get rewritten. Plan for ~1–2 days of focused work and ~half a day of test-stub re-plumbing. agents.py barely moves.
