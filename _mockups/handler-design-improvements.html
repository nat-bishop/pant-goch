HANDLER · design — improving the authoring surface
2026·05·11· handler-rebuild
Confidential — Internal

Make the LLM earn its keep
without making the game harder to balance.

The LYNX-EXFIL mission is mechanically tight but narratively thin — one named moment, seven generic archetypes, and dispatches that read as state-ticks rather than story pivots. This memo catalogues every lever for fixing that, ranked by balance-impact and authoring lift, and ends in a recommended sequence.

21 options catalogued
14 require zero new mechanics
1 recommended next step
§ 1
Diagnosis — why the story is boring
The fix follows the cause
A
Mechanical surface is small
7 archetypes, of which only ~3 are typically valid per cycle. Most cycles read the same shape: progress papers, divert, hold.
B
Only one named moment per mission
kestrel_sacrifice is the sole set-piece. Every other cycle is a transactional state-tick with no dramatic punctuation.
C
Dispatches narrate, never pivot
The renderer translates a quality movement into prose. Nothing about the world has shifted — only a number ticked. The story has no pivots, only a gradient.

01
More moments per mission
The schema supports N moments. The mission has one. Author 4–5 more — that's the highest-leverage change available.
No mechanics Weekend
+
The gap
HANDLER_SPEC_V2 describes moments as the load-bearing dramatic surface — the things the player remembers. LYNX-EXFIL has exactly one (kestrel_sacrifice). The author wrote a system for set-pieces and then wrote one set-piece.
What to add — examples
# lynx_exfil.yaml — extend `moments:` block

- id: lynx_spots_tail
  fires_at_most: once_per_mission
  when:
    kind: and
    of:
      - { kind: quality_lte, quality: agent[LYNX].cover, value: 4 }
      - { kind: quality_gte, quality: mission.extraction_stage, value: 1 }
  intent: |
    LYNX clocks a tail near the safe-house approach. Not yet pursuit —
    # still observation. The player feels the perimeter close one click.
  tone: "observational, clipped, present-tense"
  effects:
    - { quality: agent[LYNX].cover, value: -1, op: add }

- id: directorate_morning_brief
  fires_at_most: once_per_mission
  when: { kind: quality_equals, quality: mission.cycles_remaining, value: 3 }
  intent: |
    A directorate cable surfaces — the sweep is being widened.
  effects: []  # pure narrative beat — see #2
Decision-space delta
Same archetype menu, but the cycle now feels different because the rendered scene has a discrete dramatic event. Players remember moments; players forget ticks.
02
Non-load-bearing moments
Moments don't have to change outcomes. effects: [] turns a moment into a pure scene the renderer must surface.
No mechanics Hours
+
Why this is unlocked
The current schema treats effects as required but happily accepts an empty list. The orchestration in cycle.py still fires the moment, the renderer still surfaces it — it just doesn't move state. That's a pure scene with zero balance risk.
When to use
Atmospheric beats. Worldbuilding moments. Things that should happen in fiction but shouldn't shift mechanics. The directorate's morning brief leaks. KESTREL passes a graveyard at dawn. LYNX's safehouse landlord asks too many questions.
Decision-space delta
Zero on mechanics. Significant on tone — these are the moments that make the world feel populated rather than transactional.
03
Cover band descriptors
Cover values feed the renderer as raw numbers. Add band descriptors and the renderer gains in-fiction texture for every cycle, not just stage transitions.
No mechanics 1 hour
+
The gap
quality_descriptors: in lynx_exfil.yaml only covers mission.extraction_stage. Cover values are passed to the LLM as bare integers — and a 4B model renders integers blandly.
The fix
quality_descriptors:
  agent[LYNX].cover:
    bands:
      "6-9": "moving freely; the city does not see her"
      "4-5": "watched but not pursued; ordinary tradecraft holds"
      "2-3": "the perimeter has closed; her routes are constrained"
      "1":   "hours from collapse; a single mistake ends her"
  agent[KESTREL].cover:
    bands:
      "7-9": "intact, working her separate op"
      "4-6": "surfaced; the directorate has her on a list"
      "1-3": "burned to the surface; she will not survive another cycle of attention"
Before / after
State: agent[LYNX].cover = 3.
Renderer prompt receives: "agent[LYNX].cover": 3.
Output: "I made the drop. Cover is holding."
State: agent[LYNX].cover = 3.
Renderer prompt receives: "agent[LYNX]": "the perimeter has closed; her routes are constrained".
Output: "I made the drop. Two men at the south end of the platform — same coats both ways. Routes are getting thin."
Why this is highest-ROI
Every cycle, every dispatch reads the cover value. A one-hour edit improves prose density across the entire mission. There's no more efficient lever in this whole memo.
04
Mission-specific archetypes
Every archetype in LYNX-EXFIL is a generic verb. Bespoke per-mission archetypes carry unique flavor at the same balance cost as generic ones.
Mechanics added Days
+
The gap
The current archetype menu (DIVERSION, RETRIEVE, HOLD) could be the same for any mission. There's nothing about LYNX-EXFIL — its city, its agents, its specific history — encoded in the verbs.
Add 2–3 bespoke per mission
- id: LYNX_RECONTACTS_OLD_HANDLER
  intent: "Reach back to her academy handler. Old debt comes due."
  when: { kind: quality_lte, quality: agent[LYNX].cover, value: 4 }
  params: []
  effects:
    - { quality: mission.extraction_stage, value: 1, op: add }
    - { quality: agent[LYNX].cover,        value: -1, op: add }

- id: KESTREL_LEVERAGES_DIRECTORATE_INTERN
  intent: "Burn a recruit asset for one cycle of clean lanes."
  when: { kind: quality_gte, quality: agent[KESTREL].cover, value: 5 }
  params: []
  effects:
    - { quality: agent[LYNX].cover_protected, value: true, op: set }
    - { quality: agent[KESTREL].cover,         value: -2,  op: add }
Why this beats generic archetypes
Same balance complexity (a handful of new effects), wildly more memorable. The author writes the unique flavor once; the renderer picks it up for free. The "old academy handler" becomes a recurring authored fact the player can pattern-match across missions.
05
Richer dossier facts
Dossiers carry voice register and situation. They could carry operational facts the renderer pulls from naturally — known contacts, recent ops, personal stakes.
No mechanics Hours
+
Current vs proposed
- id: LYNX
  voice_register: "terse, observational..."
  voice_details: |
    Two years deep cover...
  situation: |
    Inside the city on partial cover...
- id: LYNX
  voice_register: "terse, observational..."
  voice_details: |
    Two years deep cover...
  situation: |
    Inside the city on partial cover...
  operational_facts:                     # NEW
    - "Cover identity: schoolteacher in District 4."
    - "Has a fallback contact at the eastern train depot — never used."
    - "Lost an asset in Vienna six months ago. The directorate's file
       on her may still reference it."
    - "Speaks the local language; her accent is regional, not flagged."
  personal_stakes:                       # NEW
    - "Mother in the home country. Letters intercepted, never delivered."
Why this matters
The renderer is given these facts in the system prompt as permitted callbacks — it can reference them when they fit, but never invent new ones. This gives the LLM authored material to riff off without the hallucination-and-forget cycle.
06
Moment → archetype unlocks
When a moment fires, it can unlock a previously unavailable archetype. The mechanical state change has a visible decision-tree consequence.
One quality bit Hours
+
Why this is free
No engine change required. A moment sets a quality; an archetype's when: reads it. The player-felt consequence is huge — they see authorising the moment opened a new option in the following cycle.
Concrete pattern
# Moment
- id: kestrel_sacrifice
  effects:
    - { quality: agent[KESTREL].cover,           value: 0,    op: set }
    - { quality: mission.extraction_stage,      value: 1,    op: add }
    - { quality: mission.northern_lanes_open,   value: true, op: set }  # NEW

# Newly-unlocked archetype
- id: RUN_EXFIL_VIA_NORTH
  intent: "Use the cleared northern route. Faster, no cover hit."
  when:
    kind: and
    of:
      - { kind: quality_equals, quality: mission.northern_lanes_open, value: true }
      - { kind: quality_equals, quality: mission.extraction_stage,    value: 2 }
  effects:
    - { quality: mission.extraction_stage, value: 3,  op: set }
    # Note: no cover cost — KESTREL paid it earlier
Decision-space delta
Moments stop being one-time prose punctuation. They become branch points in the decision tree. The player who authorises kestrel_sacrifice next cycle sees a different option set than the player who didn't. Authored, deterministic, no LLM in the loop.
07
Engine-computed act phase
Spine derives an "act" from state — pure function of stage, cycles remaining, cover bands. SoP and renderer prompts get this as guidance.
Prompt-only Hours
+
The mechanic
# spine.py — pure function, no I/O
def derive_act_phase(state: State) -> ActPhase:
    stage = state.qualities["mission.extraction_stage"]
    remaining = state.qualities["mission.cycles_remaining"]
    lynx = state.qualities["agent[LYNX].cover"]

    if stage == 0 and remaining >= 4:    return "setup"
    if stage >= 2 and remaining <= 2: return "climax"
    if lynx <= 2:                       return "crisis"
    return "complication"
In the renderer prompt
"I made the drop. Two men at the south end of the platform — same coats both ways. Routes are getting thin."
Renderer told: act_phase=climax · "surface tension; do not resolve"

"Drop made. Two men south end of the platform — same coats both ways, no commuter rhythm. They aren't moving yet. They will."
Decision-space delta
None. Pure rendering signal. But every cycle now reads with the appropriate dramatic register, and the model has one more cheap constraint that nudges it away from flatness.

Dramatic-question SoP framing
SoP currently summarises state. Author per-phase "dramatic question" templates so every memo is about something.
Prompt-only Hours
+
The pattern

# In the SoP system prompt
"Open the memo by naming this cycle's dramatic question — given the

Before / after

"Is KESTREL still useful, or do we cut her loose? Her cover is down to 5 and the directorate's morning sweep widens tomorrow. LYNX is at 3 with the papers in position. Two cycles. We need a decision."
09
Tension thermometer signal
Engine tracks cover delta this cycle. Sharp drops → urgent prose. Steady state → measured prose. Pure rendering nudge.
Prompt-only Hours
+
The signal
# Engine computes from state delta this cycle
tension = sum(abs(d) for d in cover_deltas)
band = "steady"     if tension <= 1
       else "escalating" if tension <= 3
       else "crisis"

# Renderer prompt addition (one line)
"Tone band this cycle: {band}. Match sentence rhythm accordingly."
Why this works on a 4B model
4B models follow constrained tonal cues better than they improvise tone from first principles. A single explicit band label gives the renderer a discrete dial to set, cheaper than asking it to "judge" tension itself.
10
"Story so far" digest
Engine compresses prior dispatches into a 2–3 line summary the renderer reads instead of the full log. A 4B model handles continuity dramatically better with a digest than a transcript.
Prompt-only Days
+
The mechanism
After each cycle, a small dedicated summariser call (or a templated engine-side reduction over the dispatch + state delta) emits one line. The accumulated digest grows cycle-by-cycle. Renderer reads the digest, not the full dispatch log — cheaper context, more reliable callbacks.
Why for a 4B
Long context is where small models drift. A 6-line digest fits in any window and surfaces the salient facts without forcing the model to read and re-prioritise multi-paragraph dispatches every cycle.
11
Standing orders
Per-mission persistent constraints the renderer must honor. "LYNX must not be photographed again." "The Vienna network is offline." Authored prose-rules, no mechanical effect.
No mechanics Hours
+
Pattern
standing_orders:
  - "LYNX must not be photographed again. The directorate already has one image."
  - "The Vienna network is offline — do not reference Vienna assets as available."
  - "All eastern train references are clean — that line has not been compromised."
In prompts
Injected into both SoP and renderer system prompts as negative space — things that constrain what the prose can claim. Costs nothing mechanically; massively improves consistency on a 4B model.
12
Voice-of-the-opposition cycles
One cycle in N, the SoP isn't from Operations Desk — it's an intercepted directorate cable. Pure prompt change, hugely different feel.
Prompt-only Hours
+
The trigger
Engine fires on a predicate (e.g., "first cycle after cover band drops to 'pursued'") and swaps the SoP agent's voice register for that single call. Renderer phase unchanged.
Effect on player
They suddenly see their own situation through the opposition's lens. Cheap, dramatic, deeply genre-correct.

Cycle-open vignettes

§ 4
Smaller architectural options
If schema underuse isn't enough

A · Authored moment library, shared across missions

Low balance impact 2–3 weeks lift No new agent

The same "shape grammar" idea sketched earlier — but without an LLM proposal layer. The author writes ~30–50 reusable moment shapes at the genre level once, each with concrete predicates and effects. Each mission inherits a subset and binds them to its specific qualities.

What "shape" means concretely

# library/moments/sacrifice.yaml — written ONCE for the whole genre
id: SACRIFICE
params: [agent_pays, agent_benefits, benefit_quality]
when_template:
  kind: and
  of:
    - { kind: quality_lte, quality: agent[$agent_pays].cover, value: 5 }
    - { kind: quality_gt,  quality: agent[$agent_pays].cover, value: 0 }
    - { kind: quality_lte, quality: mission.cycles_remaining,    value: 2 }
effects_template:
  - { quality: agent[$agent_pays].cover, value: 0,    op: set }
  - { quality: $benefit_quality,         value: 1,    op: add }
  - { quality: agent[$agent_benefits].cover_protected, value: true, op: set }
must_communicate:
  - "the cost is permanent"
  - "the choice is deliberate, not accidental"
tone: "solemn, present-tense"

Per-mission usage shrinks to one line

# lynx_exfil.yaml — kestrel_sacrifice becomes a binding
moment_bindings:
  - shape: SACRIFICE
    id: kestrel_sacrifice
    params:
      agent_pays: KESTREL
      agent_benefits: LYNX
      benefit_quality: mission.extraction_stage

The 6 shapes worth writing

  • SACRIFICE — agent A spends to benefit agent B
  • REVEAL — a dossier fact becomes mechanically active
  • PIVOT — a new mission quality is introduced mid-run
  • BURN — a previously-protected route closes permanently
  • BINDING — two qualities become coupled (one moves, the other follows)
  • CALLBACK — a prior moment's fact gates a new option

Why this is the right next architectural step

  • Engine still knows everything — predicates are concrete after binding, effects are deterministic
  • No LLM in the moment-generation loop — zero hallucination risk on the load-bearing surface
  • Per-mission authoring drops from "write 5 moments" to "write 5 one-line bindings"
  • Mission #4 is the same authoring cost as mission #1

B · Player-typed agent queries

Zero balance impact 1 week lift Fits 4B

Before authorising, the player can type one question to either agent. The LLM answers in voice, grounded in state + dispatch log + dossier + standing orders. The player probes before committing.

Flow

Cycle opens. SoP renders. Drafter emits 4 options.
Player can type one query. Free text, ≤120 chars. Routed to one agent.
Query agent answers in voice. Stateless one-shot, same prompt structure as renderer. Bounded output (~3 sentences).
Player authorises. Same option set; choice now reasoned with player-elicited context.

Example transcript

[Cycle 4 · LYNX cover 3 · stage 2]

PLAYER: "KESTREL, can you cover the eastern station tonight?"

KESTREL: "I can. There's a watcher on the west platform —
         same one from yesterday morning. If I draw him east I
         buy LYNX one clean window. After that I'm visible to the
         directorate's morning report."

[Player now authorises with new context.
 Same 4 options, but the reasoning is changed.]

Why this proves the LLM

  • The question is player-generated — authoring fundamentally cannot fake this
  • Adds a verb (query) without adding mechanics (the engine doesn't change)
  • Every playthrough has a unique elicited context
  • Tiny call shape — perfect for 4B

C · Engine-narrated dispatch coda

Zero balance impact 1–2 days lift No LLM call

After each rendered dispatch, a tiny deterministic engine pass appends one line of authored prose drawn from a phase-tagged library. Pure ambient content. The renderer doesn't know it's happening.

Library shape

codas:
  - when: { kind: cover_dropped_this_cycle, agent: LYNX }
    lines:
      - "The directorate's morning sweep moved one block south."
      - "A second pair of watchers settled on the eastern platform."
      - "The watch list grew by one name. Hers."

  - when: { kind: moment_fired, moment: kestrel_sacrifice }
    lines:
      - "KESTREL's last cable was sent at 0312. There has been nothing since."

What this buys

  • Editorial control over every cycle's closing beat
  • Zero LLM cost, zero hallucination
  • The engine gets to "speak" — surfacing world-side reactions the agents wouldn't see

J · JIT moment proposals (Tier 2)

HIGH balance impact 3–4 weeks lift New agent

Author writes shape grammar (as in option A). At runtime, a small LLM call proposes which shape fits the current state and emits a parameter binding. Engine validates, computes magnitudes, fires. The LLM never picks numbers, never picks effects — only which authored shape applies and how to bind its parameters.

Five engine gaps that block this today

  • Moment is loaded once from YAML; no constructor path from LLM output
  • No effect grammar — current Effects can do anything to anything
  • No mid-run quality introduction; make_initial_state is the only quality source
  • No MomentProposed/MomentInstantiated events for fold
  • No proposal phase in cycle.py's orchestration sequence

Cost-honest scope

  • ~500–800 lines of engine code
  • One new agent (small structured output, fits 4B)
  • Two new event classes + fold rules
  • Real risk of balance regression — JIT moments need explicit magnitude heuristics

When this is right: after 3+ missions are shipped on the simpler authoring stack and author-fatigue is the demonstrated bottleneck. Not before.

X · Cross-mission agent memory (Tier 2)

Low mission-balance impact 2–3 weeks lift Campaign architecture

LYNX survives Op. LYNX-EXFIL with cover=2 and shows up in Op. NIGHTBIRD three months later. Renderer references the scars. Drafter's options are flavored by her history. New cross-mission state object the engine carries.

What gets persisted

  • Final cover band per agent
  • Moments fired (which sacrifices, which reveals)
  • Outcome of each mission
  • Author-tagged "scar" facts: persistent ledger of what happened to whom

What this buys

A single mission's tree is unchanged, but the campaign compounds. The same mechanical choice in mission 4 reads differently because of mission 1.

Honest cost

Most of the engine is mission-scoped. Adding a campaign layer means another state machine, another persistence layer, another invariants surface. Worth it once 2+ missions exist.

P · Procedural mission generation (Tier 2)

Low intra-mission impact 4+ weeks lift Needs > 4B model

Author writes ~1 page of mission flavor (locale, target, agents, threat shape). LLM emits the YAML. Engine validates and runs deterministically.

Why a 4B can't do this

Mission YAML generation requires holding the entire schema in context, writing internally consistent predicates, and balancing magnitudes. This is a job for a larger model run as a build-time tool — not the runtime LLM.

The realistic split

  • Build-time: larger model generates mission YAML from author seed (Sonnet/Opus)
  • Runtime: 4B continues to do SoP / drafter / renderer on the generated mission

When to do this

After the genre's authoring patterns are well-established — i.e., 3–5 hand-written missions exist as the corpus the larger model learns from. Doing this first means generating from no examples.

§ 6
Recommended sequence
Cheapest leverage first; commit only when the prior step doesn't suffice
Step 1 · This week
Use the schema you have
Ship items 1, 2, 3, 5, 7, 8, 9, 11. Eight changes, all zero-balance-impact, all hours-to-days. The mission may already feel 70% less boring.
Cost: ~1 week
Step 2 · Then assess
Add moment chains + bespoke archetypes
Items 4, 6, 13. Mission gets discrete branch points and authored verbs that are unique to it. Still no new engine systems.
Cost: ~2 weeks
Step 3 · If thin
Add player queries (B)
Adds the only thing the current loop is missing — player agency between authorise-presses. Zero balance impact, real decision-space expansion, makes the LLM essential at the turn level.
Cost: ~1 week
Step 4 · If author-fatigued
Build moment shape library (A)
Only when 3+ missions exist and per-mission moment authoring is the demonstrated bottleneck. Library investment amortises across all future missions.
Cost: ~3 weeks
What's deliberately NOT in the sequence: JIT moments (J), cross-mission memory (X), procedural generation (P). Each has merit but each is a Tier 2 architectural commitment. Each should be triggered by a specific demonstrated bottleneck after Step 4 — not pursued speculatively. The prior version of this game died from speculative mechanics. The principle stands.
