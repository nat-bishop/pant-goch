Mockup comparison

Debug menu — four UI designs

Same v1 feature set (pacing sparklines, tick log, canon ledger, beat inspector) rendered four different ways. Pick the one whose philosophy fits how you actually want to debug.

D1 Tabbed Dock

Right-side panel, one tab at a time

Orthodox UI. Inbox stays visible on the left; debug panel docks to the right with a tab strip. Click a tab, see one panel at a time. Click a sparkline → drilldown replaces the pacing view with a back button.

familiar low-density inbox-adjacent
Interactions
  • Click tab — switch panel
  • Click sparkline row — drill to cause attribution
  • Click tick row — expand JSON
  • Click beat in list — predicate inspector
D2 Dashboard

2×2 grid, all panels at once, dark

Observability-tool aesthetic. Every panel visible in its own tile simultaneously. Dark theme. Sparkline points have hover tooltips with cause. Cause-attribution drills inline within the pacing tile.

dense always-on peripheral-aware
Interactions
  • Hover sparkline point — tooltip with tick + value + cause
  • Click sparkline row — inline cause+blocked drill
  • Click tick row — expand JSON
  • Beat dropdown — switch inspector target
D3 Command Palette

Type your question, see one answer

Cmd+K-style. One big input bar; suggestions narrow as you type; one result view at a time. Supports natural-language queries like why didn't recognition fire.

keyboard-first low-chrome deliberate
Interactions
  • Type — fuzzy-match suggestions appear
  • ↑/↓ arrow nav, Enter open, Esc clear
  • Queries: creator_affect, tick 6, blocked, canon name, why didn't aria.bargain_betrayed fire
D4 Inline Annotations

No separate panel — debug data on each email

Diegetic. Each email gets a debug strip below it (tick, fired beat, classify, deltas). Player messages show extracted canon candidates as chips. Floating sparkline tile + status pill. Toggle the overlay off to read the inbox normally.

in-context zero-switch novel
Interactions
  • Toggle overlay on/off (top-right button)
  • Click annotation strip — expand TickDecision detail
  • Click beat name in any strip — beat inspector modal
  • Click float-tile sparkline — quality drilldown modal
  • Click bottom-left status pill — canon modal
All four mockups share identical mock data (qualities creator_affect, creature_grievance, bargain_replies, recognition_replies; beats from the actual scenario; an 8-tick session). Every interactive element listed above is wired up — click around.
