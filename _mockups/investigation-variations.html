Investigation game variants · three ways to surface progression

The verb is probing. The question is whether she's real.

Companion artifact
Investigation variations · v0.1
3 designs · same example transcript

The shared premise — "Find out if she's real."

The Office says Aria is a synthetic counterpart trained on a deceased employee's records. Aria says she is the deceased employee, uploaded after death. One of them is lying. Fourteen sessions to figure out which.

Free-text conversation is the verb. Each variation differs in how the game surfaces what you're learning — the panel beside the email thread that turns a long chat into a felt investigation. All three use the same engine pieces (chat agent renders Aria; an extractor pass runs on Aria's outputs; authored content nodes gate by topic). They differ in what the player sees and how they interact with it.

The example conversation below is the same in all three variations — so you can compare apples to apples.

How it works in the engine

One change to the extractor

Today, the extractor runs on the player's output to harvest canon. In V1, an additional pass runs on Aria's output after each chat-agent turn. It produces structured notes:

{text, category, salience} where category is one of memory_claim, identity_claim, environmental_detail, or self_reference.

State lives in one new field

state.aria_notes: list[Note]. Append-only. The UI subscribes and renders the notebook chronologically.

Player tagging is one cheap interaction

Tap a note → pick trust / suspicious / contradicts. That sets note.player_flag. No prose typing required to use the notebook — just a tap. The flag becomes a predicate variable.

Contradiction detection is authored, not LLM

Pairs of authored memory claims are tagged with a contradicts_with key. When both fire, both notes get a "contradicts" flag automatically — the player sees the conflict surface itself.

Why this surfaces progression

The notebook is a visible record of what the player has learned. By Day 7, it's pages long — literally pages. The player can scroll back, re-read, see their own theory forming. Suspicious flags accumulate. Contradictions show up in red. The screen tells the same story as the player's head.

How it works in the engine

Topic extraction routes the conversation

The extractor pass on each player message identifies topics mentioned: {lake, priya, cafeteria, document_metaphor, ...}. A topic registry maps topics to authored beat IDs.

When the player asks about priya, the engine fires the authored beat aria.priya_memory — which carries a specific detail only the real person would know (or only trained data would produce in that texture).

Slots are authored content nodes

Each sub-investigation has 3–5 authored slots. Filling a slot is a side-effect of a specific authored beat firing (e.g., the priya_memory beat declares fills_slot: memories.priya_drowning).

Threads are auto-generated

When Aria's output contains a named entity or noun phrase the player hasn't probed, a thread chip appears. When the player asks about it, the chip greys out.

"Present" is the verdict moment

When at least one slot in each column is filled, the player can press Present — commit a verdict early. Otherwise it resolves on Day 14.

Why this surfaces progression

The case board shows the player exactly what they're working toward and how far they've gotten. Three progress bars. A finite thread list. A "Present" button that lights up when you have enough. The Phoenix Wright loop: collect, examine, present.

03
Variation · in-text annotation
The Transcript Annotator
The investigation happens inside the transcript. The player highlights specific phrases Aria says and tags them — Memory, Suspicious, Follow up. Highlights cluster into patterns automatically. The game stays out of the way; the player is the analyst. Closest to a real detective's transcript: marked up, marginal, alive.

How it works in the engine

Aria's output is sentence-segmented

When the chat agent renders Aria's reply, the result is split into clickable spans (sentences or noun phrases). Each span is hoverable; clicking opens a small menu: Memory / Suspicious / Follow up / Cancel.

Annotations live in state, indexed by span

state.annotations: list[Annotation] where Annotation = {session_id, span_id, category, day}. Append-only. UI re-renders highlights from this list.

Pattern detection is a small post-process

After each annotation, a lightweight detector runs over the annotation set:

· Recurrence: same noun phrase appears in 3+ annotations → surface a "recurs ×3" pattern card.
· Clusters: annotations on the same authored topic get grouped.
· Contradictions: two annotated spans tagged with conflicting authored facts trigger a contradiction card.

Annotation counts drive eligibility

Predicates like SuspiciousCountGte(5) become available. Specific authored beats unlock when annotation patterns match (e.g., the Office "checks in" when suspicious count crosses a threshold).

Why this surfaces progression

The player does the analysis themselves. Each highlight is a small commitment — I think this matters. Highlights accumulate visually; patterns emerge from density. The transcript stops being a chat and becomes a marked-up document. The player feels like a detective with a real case.

Trade-offs at a glance — same conversation, three games.

All three use the same example transcript above and the same underlying engine. The difference is what the player does with the transcript and what the game shows them about it.
