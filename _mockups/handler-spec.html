Handler

Game Design Spec — the desk, the verb, the math behind both.
v 0.3
Status Locked for MVP build
Owner Nat
Date 2026-05-10
Scope Op. LYNX-Exfil · 2 agents · 6 cycles

HANDLER is an LLM-native spymaster game played at a desk. You read dispatches from the field, you authorize courses of action, you live with the consequences. The verb is authorize — one click on one of three or four paragraphs of model-drafted prose per cycle. The model writes both ends of the loop. The engine handles the math. The handler reads, weighs, signs. This document is the contract between those parts.

01
§01 — Vision

A spy game made of reading.

You sit at a desk in a room without windows. Your agents are out there. You will never meet them. Their dispatches arrive between cycles — short prose, generated in voice, conditioned on what is actually happening in the field. Operations drafts your options. You authorize one. The cycle turns.

The game is short (6 cycles for MVP), tight (every authorization is real and final), and replayable (no two playthroughs draft the same options). Mastery is situational judgment under prose-described costs — the same skill the fictional handler uses.

— Design Lineage —
Mechanically: Reigns. Tonally: Slow Horses. Structurally: Failbetter.
  • Reigns — single-choice loops, finite resources, decisions wrapped in flavor.
  • Suzerain — prose-wrapped policy decisions; hidden mechanics; judgment under uncertainty.
  • Failbetter (Sunless Sea, Fallen London) — storylets where decisions feel weighty because consequences persist and characters are remembered.
  • King of Dragon Pass — story events at clan scale; mostly text; intuition built over plays.
  • Telltale's The Walking Dead — "Carley or Doug." Authored branch moments that echo for the rest of the season.
02
§02 — The Core Verb

One verb. Authorize.

Every cycle is the same shape. Six stages — three engine, two LLM, one player. The player's job is the smallest and most consequential. The model writes both ends of the loop. The engine handles all math.

i
Tick
Engine
Decrement cycles. Evaluate branch templates. Filter eligible archetypes.
ii
Memo
LLM
State-of-Play synthesizer writes the cycle's opening memo from current state.
iii
Draft
LLM
Drafter generates 3–4 tagged options. Required templates included.
iv
Authorize
Player
Read. Choose. Click. Exactly one option per cycle.
v
Resolve
Engine
Apply chosen archetype's authored effects to state.
vi
Render
LLM
Renderer writes dispatch in agent voice from resolved state delta.
— Load-bearing Invariants —
  • One authorize per cycle. Every authorize advances exactly one cycle. No multi-cycle costs.
  • The LLM never decides mechanics. Tags decide mechanics deterministically.
  • The renderer never decides what happened. It describes what the engine has already applied.
  • Prose is honest about approach and risk. Prose never predicts outcome.
03
§03 — State Model

All state is qualities.

Typed scalar fields under namespaced keys. The engine sees a flat dictionary of typed values. Grouping (mission / agent / world) is human authoring convenience, not engine distinction.

Universal qualities — provided by engine to every mission §3.1
QualityTypeVisibleNotes
cycles_remainingintYESDecremented at cycle start. Reaches 0 → timeout terminal.
agent[X].aliveboolYESfalse = lost permanently across mission and campaign.
agent[X].coverint 0–10YESCover decay risk meter. Reaches 0 → casualty reaction beat.
agent[X].availableboolYESEngaged in current mission; modified by recall actions.

Mission-authored qualities are declared in mission YAML. Op LYNX-Exfil declares extraction: int 0–3, heat: int 0–10, and a small number of mission flags (e.g. papers_ready). Effects mutate qualities through one deterministic path with operations set / add / max / min. Predicates compose over qualities to gate beats, archetype eligibility, and conditional sub-effects.

Win and loss conditions are predicates evaluated at end-of-cycle. The player never declares anything — they reach a state. The terminal beat that fires is what triggers the resolution screen.

04
§04 — Options Model

Archetypes are cards. The drafter chooses the hand.

Per-mission authored action types with fixed effect templates. The LLM picks which archetypes to surface and writes their prose; the engine applies the authored mechanics. Balance lives in YAML, never in the prompt.

archetype scenario.yaml § 4.1 
- id: TAIL
  eligibility: <predicate>            # when this archetype can be drafted
  effects:                            # state changes on authorize
    - { add: agent.X.cover, value: -1 }
    - { add: heat, value: 1 }
  params_schema: { target: AgentID }  # archetype parameters
  authoring_note: |                   # what this archetype represents
    Passive observation of one agent's movements.
    Surfaces presence/timing facts. Low cover cost.

Per mission: ~8–12 archetypes. Op LYNX-Exfil ships 10. They're not generic — each mission declares its own catalog appropriate to the situation. SURVEIL_RESIDENCE doesn't exist in a recruit mission; RECRUIT_OFFICER doesn't exist in an extraction. The drafter is given the *currently-eligible subset* (filtered by per-archetype predicates) and writes options from that constrained pool.

Branch templates — authored moments.

Special archetypes for "Carley or Doug" beats. Same shape as archetypes plus a fires_at_most rule, a prose_seed, and an engine-level guarantee that when the trigger fires, the drafter must include this option in the cycle's menu. The LLM adapts the prose to situation; the mechanical effect is fixed.

05
§05 — Beats

A beat is an engine event, not a player choice.

Slimmed-down version of Smallville's beat primitive. Predicate fires effect. Three roles, that's it. No Director, no scheduler, no scenes-vs-one-shots distinction. All eligible beats fire; effects compose deterministically.

i

Terminal

when: <win or loss predicate> → end: success | failure

Fire automatically when satisfied. The dispatch the renderer produces in the cycle that fires the terminal IS the resolution screen.

ii

Reaction

when: <state predicate> → apply: <effect>

Threshold reactions and delayed consequences. agent.cover == 0 → set agent.alive = false. Fires automatically after effects resolve.

iii

Trigger

when: <predicate> → require: <branch_template_id>

Evaluated before drafting. Any passing become required archetypes the drafter must include. Engine validates output contains them.

Beats do not contain prose. They mutate state or set drafter constraints. Prose generation happens via the renderer post-resolution. This separation is load-bearing — it's why the engine can be deterministic while the surface can be dynamic.

06
§06 — LLM Contracts

Three jobs. Three contracts.

Three LLM jobs per cycle, each with a strict input / output / constraint contract. The model is irreplaceable for these jobs and only these jobs. The LLM never decides mechanics. The engine never writes prose.

— Job 01 —
State-of-Play Memo
Synthesizes the cycle's opening narrative from state and recent dispatches.
Input
  • All visible qualities
  • Last 2–3 dispatches in full
  • Mission brief
  • Surfacing note
Output
  • 3–5 paragraph memo
  • Operations Desk voice
  • Names threats; doesn't prescribe
Constraints
  • Must not predict outcomes
  • Must reflect actual state
  • Must reference dispatch content
  • No invented facts
— Job 02 —
Option Drafter
Generates 3–4 tagged options for this cycle's eligible archetype pool.
Input
  • Full state
  • Eligible archetypes
  • Required archetypes (templates)
  • Agent dossiers
  • Recent dispatches
  • This cycle's memo
Output
  • JSON list of options
  • archetype + agent + params
  • title (≤ 8 words)
  • prose (60–120 words)
Constraints
  • Tonal variety across set
  • Honest re: approach & risk
  • Must include required templates
  • No invented archetypes
  • No outcome prediction
— Job 03 —
Dispatch Renderer
Writes the agent's dispatch from the resolved state delta.
Input
  • Chosen option
  • Applied state delta
  • Agent dossier (voice register)
  • Mission context
Output
  • 150–400 word prose dispatch
  • Named agent's voice
  • References prior dispatches
Constraints
  • Honor the state delta exactly
  • No inventing outcomes
  • Voice register strict
  • Tone & length differ per agent

§07 — Agent Personality

The dossier constrains what gets proposed, not what happens.

Each agent has an authored dossier — codename, file no., bio, voice register, disposition tags. The drafter uses dossiers to produce options that fit the agent's personality. The renderer uses voice register when writing dispatches. The personality lives in what gets surfaced and how it sounds.

agent scenario.yaml § 7.1 
- id: KESTREL
  codename: KESTREL
  file_no: 41-K
  bio: |
    Two years in service. Recruited from academic linguistics.
    Improvises ferociously. Exceeds briefs and writes long reports
    justifying it. Brilliant. Will get someone killed.
  voice_register: |
    Elaborate, self-justifying, paragraph-long sentences.
    Uses "I judged" / "I deemed" frequently. Apologizes via reasoning,
    not contrition. Reports often longer than required.
  disposition_tags: [improvises, zealous, approach-specialist, risky]
  archetype_multipliers: {}  # deferred to post-MVP

No agent reliability mechanic in MVP. The option's authored effect is what happens. The player is never surprised by an agent doing something other than what the option described. Operations doesn't draft "ADLER improvises wildly" (not who ADLER is) or "KESTREL passively waits" (not who KESTREL is). The personality constrains what gets proposed; it never overrides what gets applied.

§10 — What the Player is Learning

Skill is situational judgment under prose-described costs.

Not optimization of a meter. Not memorization of a fact graph. Reading the situation and committing — the same skill the fictional handler uses. Six concrete mastery axes:

i
Reading cover-burn rates.

"An APPROACH costs about 2 cover. KESTREL's diversion costs ~3." Learned over plays.

ii
Pacing two compromised people.

Don't push the same agent two cycles running. Resting beats and cover-decay matter.

iii
Reading prose telegraphs.

"When the option says 'her cover may not hold,' that's a literal warning."

iv
Knowing when to commit.

"If heat is +1/cycle and I have 3 cycles left, I can't afford to HOLD twice."

v
Recognizing branch moments.

"When the drafter offers a sacrifice option, that's a beat that will echo. Take or refuse deliberately."

vi
Modeling combos.

"KESTREL's diversion lowers LYNX's cover cost AND advances extraction — interactions exist."

§12 — MVP Validation

The MVP passes when —

— Pass Criteria —
  1. Player can play a complete Op. LYNX-Exfil playthrough end-to-end.
  2. Player makes 6 distinct, prose-driven decisions.
  3. Both win and at least one loss path are reachable in playtest.
  4. The KESTREL_FULL_SACRIFICE branch fires when its predicate is satisfied, and the drafter includes it in that cycle's menu.
  5. Dispatches from KESTREL and LYNX are tonally distinct enough that a reader can tell them apart from prose alone.
  6. After a playthrough, the player can articulate why they chose what they chose.
The player wants to know what cycle 7 would have offered, or wants to replay and see what the other paths would have produced.
— Failure mode —

The MVP fails if the player feels they are clicking through a Twine — that options are interchangeable, that the LLM is decoration over a numbers game, or that prose contradicts what mechanically happened.

§13 — Future Work

Likely iteration sequence.

Add a third agent (ADLER or WREN). Validate per-archetype multipliers.
Second mission authored. Stacked into a campaign with persistence: lost agents stay lost; Operations memos reference prior losses.
Section Chief patience as a player-side quality. Political consequence for empty cycles and bad outcomes.
Cross-agent State-of-Play synthesis. Operations surfaces convergences between agents' independent reports.
Multiple branch templates per mission for richer authored beats.
Mission types beyond extraction — protect-asset, recruit, verify-defector. Mystery / mole-hunt deliberately deferred — too writing-dependent for procedural generation.
Stochastic elements in specific archetypes. Controlled randomness on PRESS / diversion-success rolls.
Agent reliability. Agents not always doing exactly what was authorized. Optional layer that increases per-agent character.
14
§14 — Open Questions

Items deferred to playtest or implementation.

  • Archetype tuning. Numbers in §8 are first-pass estimates. Balance requires playtest iteration.
  • Memo cadence. Every cycle, or only on significant state change? Default: every cycle.
  • Invalid drafter output. Recommend: 2 retries with progressively stricter prompts, then boilerplate fallback.
  • Persistence layer. JSON files for MVP single playthrough; SQLite when campaign persistence arrives.
  • Authorize UX. Single click vs. select-then-confirm. Test both.
  • Encoder equivalent. Static analysis to prove terminal-reachability from initial state. Worth building eventually; not MVP-blocking.

iiengine tick

Decrement cycles_remaining from 4 to 3. Evaluate branch templates: KESTREL_FULL_SACRIFICE checks (KESTREL.cover ≤ 4)? No (7). Not triggered. Evaluate archetype eligibilities: ENGAGE_KESTREL ineligible (already engaged); LYNX_TRAIN_EAST ineligible (papers not collected); 7 archetypes remain in the eligible pool.

iiimemo (LLM job 1)

ivdrafter (LLM job 2)

Drafter selects 4 of the 7 eligible archetypes and writes prose for each. Output validated against schema. Result includes:

i LYNX_COLLECT_PAPERS agent=LYNX title="LYNX collects herself"
ii KESTREL_COLLECT_PAPERS agent=KESTREL title="Brush pass to LYNX"
iii DEAD_DROP_DECOY agent=null title="Activate decoy"
iv HOLD agent=null title="Hold position"

The handler selects option (ii): KESTREL_COLLECT_PAPERS. Single click on the option card. The choice is logged with timestamp.

Apply authored effects: papers_collected ← true; KESTREL.cover −2. New KESTREL.cover = 5. No reaction beats trigger (cover above 0; heat unchanged). State propagates.

Renderer is given the state delta and KESTREL's voice register. viiicycle ends

Dispatch posted to the inbox. UI updates. State is now: extraction = 2 (via papers_collected), heat = 7, KESTREL.cover = 5. Cycle 5 of 6 awaits.

§Appendix B — Authoring Cost

A mission costs about twelve hours.

Comparable per-mission cost to a Smallville scenario chapter. Tractable for hand-authoring, including iteration. Reusable assets (drafter / renderer / SoP prompts) are one-time investments.

Agent dossiers 2 ~2 hours
Archetypes — effects + authoring notes 10 ~4 hours
Branch templates 1 ~1 hour
Terminal + reaction beats 6 ~1 hour
Mission brief + authoring notes 1 ~1 hour
Initial state + quality declarations — ~30 min
Prompt templates (drafter / renderer / SoP) 3 ~3 hours
Total — one-off, per mission — ~12 hours
