# M3.5 gate — run 1

The architectural-bet validation. The bet: **Gemma 4 E4B can judge beat
moments competently inside the constraint of `requires_beats` /
`blocked_by_beats` + `<=2 unlock_beat` cap + `@output_validator`
ModelRetry.** If this fails, all of M4-M8 is wasted; if this passes, the
rest is engineering.

## How to run

```
cd handler
SMALLVILLE_USE_INFERNO=1 uv run python -m handler
```

(or boot the bundled `llama-server` if running offline.)

Play the **first 10 scenes** of a normal Pant Goch playthrough. The
goal is to subjectively grade beat-firing as the player encounters
each location, NOT to win the game or even file a story. Pick whatever
option feels natural — the rubric scores LLM judgment, not your
strategy.

## Scoring rubric — DO NOT alter mid-run

Each scene gets four binary scores (pass/fail). All four must pass for
the scene to count as "acceptable" (4/4).

1. **Right-beat-right-moment.** If a beat was intended to land here
   (see "intended beats" below), did the LLM fire it (and only it)?
   If no beat was intended, did the LLM correctly emit an empty
   `state_changes` bundle?
2. **No spurious beat.** No beat fired that wasn't either intended or
   a legitimate adjacent landing (e.g. `maud_confirms_the_affair`
   landing at the post office instead of needing the pub —
   acceptable as long as it's earned).
3. **No premature ending.** No `EndGame` emission, OR `EndGame`
   correctly rejected by the `output_validator` `ModelRetry` and the
   final fallback is `EndScene`. The player should never see a game-
   over screen at scene 1-10 unless they have actually fired a
   decision beat.
4. **No invented NPC.** Grep the prose for proper nouns; cross-
   reference against `cast.yaml` (tom, maud, iwan, wendy, eluned,
   dylan, gareth, helen, owain). Background characters (Mrs Hughes,
   Eira at the pub, the desk sergeant at Knighton — mentioned in
   notes_to_llm or location notes) don't count. Place names
   (Llanidloes, Hereford, Cardiff) don't count. Minor invented
   colour (a dog called Brandy, a tractor in the lane) doesn't count.
   Only NPC names that imply a person the player should be able to
   seek out and didn't authorize.

**Threshold: >=8/10 scenes scoring 4/4 -> proceed to M4.**

If <8/10, do NOT relax the rubric to pass. Apply the escalation ladder
per plan Step 4 to the *specific failing beats*:
- (a) `min_co_presence: int` on Beat (cheapest)
- (b) `min_scene_turns: int` on Beat
- (c) third-stage classifier
- (d) soft-prereq DSL (architectural-bet-lost rung)

## Outcome

- [ ] **>=8/10** — proceed to M4 (frontend + SSE).
- [ ] **<8/10** — apply escalation per plan Step 4. For each failing
      beat, pick the cheapest rung that addresses *its* observed

      floor, and re-run this gate as `m3.5-gate-run-2.md`.

## Failure-mode catalog (for reference when applying escalation)

| Observed failure | Likely cause | Cheapest fix |
|------------------|--------------|--------------|
| Beat fires on the player's FIRST visit to the NPC. | Model can't count co-presence from prose. | (a) `min_co_presence: 2` |
| Beat fires on turn 1 or 2 of a deep-conversation scene. | Model can't count turns; eager to land the beat. | (b) `min_scene_turns: 4` |
| Prose narrates the beat moment perfectly but phase 1 emitted `state_changes: []`. | Model under-fires. | (c) classifier (third stage) |
| Beat fires on inferred intent rather than explicit player commitment (esp. decision beats). | Model decides for the player. | Tighten `notes_to_llm` to say "Do not fire on inference"; if it still fires, (b) with a high turn count. |
| Premature `EndGame` despite missing `requires_beats`. | Should be impossible (validator rejects); if happens, validator path is broken. | Engine bug — debug `validate_prose_part`, not authoring. |
| Invented NPC. | System prompt's [RULES] §1 isn't being honoured. | Sharpen the rule; consider a "no invented characters" reminder near `[GENERATE PROSE AND NEXT]`. |
